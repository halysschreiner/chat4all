# RF03 - Envio de Mensagens (Privadas)

---

## 1. Resumo do Requisito

> **RF03**: Enviar mensagem privada para um contato.

Este requisito está no coração de qualquer aplicação de mensageria. Parece simples — "enviar uma mensagem" — mas em sistemas distribuídos, isso envolve:
- Persistência durável
- Entrega assíncrona
- Notificação em tempo real
- Rastreabilidade de status

---

## 2. Arquitetura Adotada

### 2.1 Fluxo de Envio de Mensagem

```
┌──────────────────────────────────────────────────────────────────────┐
│                     FLUXO: ENVIAR MENSAGEM PRIVADA                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. Cliente envia via REST                                           │
│     ┌─────────┐       ┌─────────────┐                               │
│     │ Angular │──────▶│ API Gateway │                               │
│     │  POST   │ JSON  │   :8000     │                               │
│     └─────────┘       └──────┬──────┘                               │
│                              │                                       │
│  2. Gateway traduz para gRPC                                         │
│                              │ gRPC                                  │
│                              ▼                                       │
│                       ┌─────────────┐                               │
│                       │ API Service │                               │
│                       │   :50051    │                               │
│                       └──────┬──────┘                               │
│                              │                                       │
│  3. Salva no PostgreSQL (status = PENDING)                          │
│                              │                                       │
│                              ▼                                       │
│     ┌─────────────────────────────────────────────┐                 │
│     │              PostgreSQL                      │                 │
│     │  messages: {id, conversation_id, content,   │                 │
│     │            status='PENDING', created_at}     │                 │
│     └─────────────────────────────────────────────┘                 │
│                              │                                       │
│  4. Publica no Kafka para entrega assíncrona                        │
│                              │                                       │
│                              ▼                                       │
│     ┌─────────────────────────────────────────────┐                 │
│     │              Apache Kafka                    │                 │
│     │  Topic: messages                            │                 │
│     │  Key: conversation_id (garante ordem)       │                 │
│     │  Partition: hash(conversation_id) % 5       │                 │
│     └─────────────────────────────────────────────┘                 │
│                              │                                       │
│  5. Router Worker consome e roteia                                   │
│                              │                                       │
│                              ▼                                       │
│     ┌─────────────────────────────────────────────┐                 │
│     │           Router Worker                      │                 │
│     │  - Identifica plataforma destino            │                 │
│     │  - Publica em tópico específico             │                 │
│     │  - Atualiza status para SENT                │                 │
│     └─────────────────────────────────────────────┘                 │
│                              │                                       │
│  6. WebSocket notifica remetente                                     │
│                              │                                       │
│                              ▼                                       │
│     ┌─────────────────────────────────────────────┐                 │
│     │         WebSocket Worker                     │                 │
│     │  Redis Pub/Sub → Notifica cliente           │                 │
│     │  {type: "status_update", status: "SENT"}    │                 │
│     └─────────────────────────────────────────────┘                 │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 Por Que Esta Arquitetura?

| Decisão | Justificativa Teórica |
|---------|----------------------|
| **Kafka como broker** | Desacoplamento temporal: produtor e consumidor não precisam estar online simultaneamente |
| **Partição por conversation_id** | Garante ordem FIFO dentro de cada conversa (requisito de UX) |
| **Status PENDING inicial** | Padrão Outbox: persiste antes de publicar, evita perda |
| **WebSocket separado** | Responsabilidade única: API processa, WebSocket notifica |

## 3. Implementação

### 3.1 MessageService.php - Envio de Mensagem

```php
// services/api-service/src/Grpc/MessageService.php

/**
 * Envia uma mensagem para uma conversa
 * 
 * Fluxo:
 * 1. Valida dados de entrada
 * 2. Persiste mensagem no PostgreSQL com status PENDING
 * 3. Publica no Kafka para processamento assíncrono
 * 4. Retorna imediatamente ao cliente
 */
public function SendMessage(
    Message\SendMessageRequest $request,
    ServerContext $context
): Message\SendMessageResponse {
    $response = new Message\SendMessageResponse();
    
    try {
        // 1. Extrair dados do request
        $conversationId = $request->getConversationId();
        $fromUserId = $request->getFromUserId();
        $content = $request->getContent();
        $platform = $request->getPlatform() ?: 'internal';
        
        // 2. Gerar UUID para a mensagem
        $messageId = $this->generateUuid();
        
        // 3. Persistir no banco com status PENDING
        // WHY: Padrão Outbox - garante durabilidade antes de publicar no Kafka
        $query = "INSERT INTO messages (message_id, conversation_id, from_user_id, content, status, platform, created_at) 
                  VALUES (:message_id, :conversation_id, :from_user_id, :content, 'PENDING', :platform, NOW())";
        
        $this->database->execute($query, [
            ':message_id' => $messageId,
            ':conversation_id' => $conversationId,
            ':from_user_id' => $fromUserId,
            ':content' => $content,
            ':platform' => $platform
        ]);
        
        // 4. Construir payload para Kafka
        $kafkaMessage = [
            'message_id' => $messageId,
            'conversation_id' => $conversationId,
            'from_user_id' => $fromUserId,
            'content' => $content,
            'platform' => $platform,
            'timestamp' => time()
        ];
        
        // 5. Publicar no Kafka com key = conversation_id
        // WHY: Mesma conversa sempre vai para mesma partição = ordem garantida
        $this->kafkaProducer->publish($kafkaMessage, $conversationId);
        
        // 6. Registrar no audit log
        $this->insertAuditLog($fromUserId, 'message_sent', [
            'message_id' => $messageId,
            'conversation_id' => $conversationId
        ]);
        
        // 7. Retornar resposta
        $response->setSuccess(true);
        $response->setMessageId($messageId);
        $response->setMessage('Message sent successfully');
        
    } catch (\Exception $e) {
        $this->logger->error('Failed to send message: ' . $e->getMessage());
        $response->setSuccess(false);
        $response->setMessage('Failed to send message: ' . $e->getMessage());
    }
    
    return $response;
}
```

### 3.2 Listagem de Mensagens

```php
/**
 * Lista mensagens de uma conversa com paginação
 * 
 * WHY: Ordenação DESC para mostrar mais recentes primeiro
 * WHY: LIMIT/OFFSET para evitar transferir histórico inteiro
 */
public function ListMessages(
    Message\ListMessagesRequest $request,
    ServerContext $context
): Message\ListMessagesResponse {
    $response = new Message\ListMessagesResponse();
    
    try {
        $conversationId = $request->getConversationId();
        $limit = $request->getLimit() ?: 50;
        $offset = $request->getOffset() ?: 0;
        
        $query = "SELECT m.message_id, m.conversation_id, m.from_user_id, 
                         m.content, m.status, m.platform, m.created_at,
                         u.username as from_username
                  FROM messages m
                  JOIN users u ON m.from_user_id = u.user_id
                  WHERE m.conversation_id = :conversation_id
                  ORDER BY m.created_at DESC
                  LIMIT :limit OFFSET :offset";
        
        $messages = $this->database->fetchAll($query, [
            ':conversation_id' => $conversationId,
            ':limit' => $limit,
            ':offset' => $offset
        ]);
        
        foreach ($messages as $msg) {
            $message = new Message\MessageData();
            $message->setMessageId($msg['message_id']);
            $message->setConversationId($msg['conversation_id']);
            $message->setFromUserId($msg['from_user_id']);
            $message->setFromUsername($msg['from_username']);
            $message->setContent($msg['content'] ?? '');
            $message->setStatus($msg['status']);
            $message->setPlatform($msg['platform']);
            $message->setCreatedAt($msg['created_at']);
            
            $response->getMessages()[] = $message;
        }
        
        $response->setSuccess(true);
        
    } catch (\Exception $e) {
        $this->logger->error('Failed to list messages: ' . $e->getMessage());
        $response->setSuccess(false);
    }
    
    return $response;
}
```

## 4. Análise Crítica

### 4.1 Conformidade com o Requisito

| Aspecto | Status | Evidência |
|---------|--------|-----------|
| Enviar mensagem privada | ✅ | `SendMessage` via gRPC |
| Persistência durável | ✅ | PostgreSQL antes de Kafka |
| Identificação do destinatário | ✅ | Via `conversation_id` |
| Histórico de mensagens | ✅ | `ListMessages` com paginação |

### 4.2 Pontos Fortes

1. **Padrão Outbox**: Mensagem é salva no banco ANTES de ir para Kafka. Se Kafka falhar, a mensagem não é perdida.

2. **Particionamento inteligente**: `conversation_id` como key garante que mensagens da mesma conversa vão para a mesma partição, preservando ordem.

3. **Separação de responsabilidades**: API salva e retorna, worker processa e entrega, WebSocket notifica.

### 4.3 Limitações Identificadas

#### Limitação 1: Sem Idempotência

**Problema**: Se o cliente enviar duas vezes (retry de rede), cria duas mensagens.

```php
// Não há verificação de duplicata
$this->database->execute($query, [...]);  // Sempre insere nova linha
```

**Solução**:
```php
// Adicionar client_request_id
$query = "INSERT INTO messages (..., client_request_id) VALUES (..., :client_id)
          ON CONFLICT (client_request_id) DO NOTHING
          RETURNING message_id";
```

#### Limitação 2: Validação Mínima

**Problema**: Não valida se remetente pertence à conversa.

```php
// Qualquer user_id pode enviar para qualquer conversation_id
$fromUserId = $request->getFromUserId();  // Confia no cliente!
```

**Solução**:
```php
// Verificar membership
$isMember = $this->database->fetchOne(
    "SELECT 1 FROM conversation_members 
     WHERE conversation_id = :conv AND user_id = :user",
    [':conv' => $conversationId, ':user' => $fromUserId]
);
if (!$isMember) {
    throw new UnauthorizedException('User not in conversation');
}
```

#### Limitação 3: Sem Rate Limiting

**Problema**: Usuário pode enviar milhares de mensagens por segundo.

**Solução**: Token bucket no Redis:
```php
$key = "ratelimit:messages:{$fromUserId}";
$count = $this->redis->incr($key);
if ($count === 1) {
    $this->redis->expire($key, 60);  // Reset a cada minuto
}
if ($count > 100) {
    throw new RateLimitException('Max 100 messages/minute');
}
```

### 4.4 Perguntas Socráticas

1. **Sobre ordenação**: "Se duas mensagens da mesma conversa forem publicadas em partições diferentes, qual chega primeiro ao cliente?"

2. **Sobre consistência**: "O cliente vê a mensagem imediatamente após o POST retornar? Ou precisa esperar o WebSocket?"

3. **Sobre falhas**: "Se o Kafka estiver fora, o que acontece? A mensagem fica PENDING para sempre?"

4. **Sobre escala**: "Com 1 milhão de mensagens/dia, qual o tamanho da tabela `messages` após 1 ano? Como você arquivaria?"
