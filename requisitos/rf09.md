# RF09 - Gerenciamento de Conversas

---

## 1. Resumo do Requisito

> **RF09 - Gerenciamento de Conversas**:
> - Suporte a conversas do tipo `private` (chat privado) e `group` (grupo).
> - Registro de membros da conversa com papéis: `owner`, `admin`, `member`.
> - Rastrear última leitura (`last_read_at`) por usuário em cada conversa.

### Dependências com Outros Requisitos

| Requisito | Tipo de Dependência | Descrição |
|-----------|---------------------|-----------|
| **RF03** | Uso Downstream | Mensagens privadas dependem de conversas tipo `private` |
| **RF04** | Uso Downstream | Mensagens em grupo dependem de conversas tipo `group` |
| **RF06** | Integração | Status READ atualiza `last_read_at` |
| **RF02** | Autenticação | Identificação do usuário para operações |

### Conceito Teórico

RF09 implementa o **modelo de domínio** de conversas, que é a unidade fundamental de agrupamento de mensagens. A diferenciação entre `private` e `group` segue o padrão de **polimorfismo de tipo** onde a mesma entidade (conversa) tem comportamentos diferentes baseado no tipo.

**Princípios aplicados**:
- **Single Table Inheritance**: Ambos os tipos na mesma tabela com coluna discriminadora
- **Role-Based Access Control (RBAC)**: Hierarquia `owner > admin > member`
- **Denormalization**: `last_message_*` para evitar JOINs em listagem

## 2. Arquitetura de Dados

### 2.1 Modelo de Dados

```sql
┌─────────────────────────────────────────────────────────────┐
│                      conversations                          │
├─────────────────────────────────────────────────────────────┤
│ conversation_id    │ UUID PK                                │
│ type               │ 'private' | 'group'                    │
│ name               │ VARCHAR (NULL para private)            │
│ created_by         │ UUID FK users                          │
│ last_message_*     │ Desnormalização para performance       │
└─────────────────────────────────────────────────────────────┘
                              │
                              │ 1:N
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                  conversation_members                        │
├─────────────────────────────────────────────────────────────┤
│ conversation_id    │ UUID FK                                │
│ user_id            │ UUID FK                                │
│ role               │ 'owner' | 'admin' | 'member'           │
│ joined_at          │ TIMESTAMP                              │
│ last_read_at       │ TIMESTAMP (tracking de leitura)        │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Diferenças por Tipo

| Característica | Private | Group |
|----------------|---------|-------|
| **Membros** | Exatamente 2 | 2 a N |
| **Nome** | NULL (usa nome do outro usuário) | Obrigatório |
| **Criação** | Idempotente (não duplica) | Sempre cria novo |
| **Roles** | owner + member | owner + admins + members |
| **Saída** | Não permitida (desativa) | Permitida |

### 2.3 Hierarquia de Roles

```
┌─────────────────────────────────────────────────────────────┐
│                    HIERARQUIA DE ROLES                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   OWNER  ──────────────────────────────────────────────────│
│     │    Pode: tudo + deletar grupo + transferir ownership │
│     │                                                       │
│     ▼                                                       │
│   ADMIN  ──────────────────────────────────────────────────│
│     │    Pode: gerenciar membros + editar grupo             │
│     │                                                       │
│     ▼                                                       │
│   MEMBER ──────────────────────────────────────────────────│
│          Pode: enviar mensagens + sair do grupo             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 3. Stack Tecnológica

| Componente | Tecnologia | Justificativa |
|------------|------------|---------------|
| **Banco de Dados** | PostgreSQL | ACID para dados relacionais |
| **Constraints** | CHECK | Validação de tipos no banco |
| **Índices** | B-tree | Busca por conversation_id e user_id |

### Trade-off: Desnormalização

**Decisão**: Campos `last_message_*` na tabela `conversations`.

**Prós**:
- Listagem de conversas em query única (sem JOIN em messages)
- Ordenação por última atividade O(n log n) vs O(n²)

**Contras**:
- Duplicação de dados
- Necessidade de atualizar em cada nova mensagem

**Justificativa**: Leitura (listagem) é muito mais frequente que escrita (nova mensagem). Otimização válida pelo *read-heavy workload*.

## 4. Implementação

### 4.1 Schema do Banco (`init-db.sql`)

```sql
-- Conversas
CREATE TABLE IF NOT EXISTS conversations (
    conversation_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    type VARCHAR(20) NOT NULL CHECK (type IN ('private', 'group')),
    name VARCHAR(255), -- Nome do grupo (NULL para privadas)
    created_by UUID NOT NULL REFERENCES users(user_id),
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    
    -- Desnormalização: última mensagem para listagem rápida
    last_message_id UUID,
    last_message_at TIMESTAMP,
    last_message_snippet TEXT,
    
    is_active BOOLEAN DEFAULT true
);

-- Membros da conversa
CREATE TABLE IF NOT EXISTS conversation_members (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    conversation_id UUID NOT NULL REFERENCES conversations(conversation_id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    role VARCHAR(20) DEFAULT 'member' CHECK (role IN ('owner', 'admin', 'member')),
    joined_at TIMESTAMP DEFAULT NOW(),
    last_read_at TIMESTAMP,  -- Tracking de leitura por usuário
    
    UNIQUE(conversation_id, user_id)
);

CREATE INDEX idx_conversation_members_conv ON conversation_members(conversation_id);
CREATE INDEX idx_conversation_members_user ON conversation_members(user_id);
```

### 4.2 Criação de Conversa Privada (`ConversationService.php`)

```php
public function CreatePrivateConversation(CreatePrivateConversationRequest $request): CreateConversationResponse
{
    $response = new CreateConversationResponse();
    
    try {
        $userId = $request->getUserId();
        $otherUserId = $request->getOtherUserId();
        
        // Validação: não pode conversar consigo mesmo
        if ($userId === $otherUserId) {
            throw new \Exception("Cannot create conversation with yourself");
        }
        
        // Buscar outro usuário (por UUID, email ou phone)
        $otherUser = $this->findUser($otherUserId);
        if (!$otherUser) {
            throw new \Exception("User not found");
        }
        $otherUserId = $otherUser['user_id'];
        
        // IDEMPOTÊNCIA: verificar se já existe
        $existingId = $this->database->checkPrivateConversationExists($userId, $otherUserId);
        
        if ($existingId) {
            $conversationData = $this->database->getConversationById($existingId);
            $response->setMessage("Conversation already exists");
        } else {
            // Criar conversa tipo 'private' (sem nome)
            $conversationId = $this->database->createConversation('private', null, $userId);
            
            // Adicionar membros com roles
            $this->database->addConversationMember($conversationId, $userId, 'owner');
            $this->database->addConversationMember($conversationId, $otherUserId, 'member');
            
            $conversationData = $this->database->getConversationById($conversationId);
            $response->setMessage("Conversation created successfully");
        }
        
        $response->setSuccess(true);
        $response->setConversation($this->mapConversation($conversationData));
        
    } catch (\Exception $e) {
        $this->logger->error("CreatePrivateConversation error: " . $e->getMessage());
        $response->setSuccess(false);
        $response->setMessage($e->getMessage());
    }
    
    return $response;
}
```

**Análise crítica**: A idempotência é garantida via `checkPrivateConversationExists`. Isso evita duplicação se o cliente retentar a requisição.

### 4.3 Verificação de Conversa Existente (`Database.php`)

```php
public function checkPrivateConversationExists(string $userId1, string $userId2): ?string
{
    // Busca conversa private onde AMBOS usuários são membros
    $stmt = $this->pdo->prepare('
        SELECT c.conversation_id
        FROM conversations c
        JOIN conversation_members cm1 ON c.conversation_id = cm1.conversation_id
        JOIN conversation_members cm2 ON c.conversation_id = cm2.conversation_id
        WHERE c.type = :type
        AND cm1.user_id = :user1
        AND cm2.user_id = :user2
        AND c.is_active = true
        LIMIT 1
    ');
    
    $stmt->execute([
        'type' => 'private',
        'user1' => $userId1,
        'user2' => $userId2
    ]);
    
    $result = $stmt->fetch();
    return $result ? $result['conversation_id'] : null;
}
```

### 4.4 Criação de Grupo (`ConversationService.php`)

```php
public function CreateGroup(CreateGroupRequest $request): CreateConversationResponse
{
    $response = new CreateConversationResponse();
    
    try {
        $userId = $request->getUserId();
        $groupName = $request->getGroupName();
        $memberIds = $request->getMemberUserIds();
        
        if (!$groupName) {
            throw new \Exception("Group name is required");
        }
        
        // Criar conversa tipo 'group' COM nome
        $conversationId = $this->database->createConversation('group', $groupName, $userId);
        
        // Criador é OWNER
        $this->database->addConversationMember($conversationId, $userId, 'owner');
        
        // Adicionar outros membros
        foreach ($memberIds as $memberId) {
            $memberUser = $this->findUser($memberId);
            
            if ($memberUser) {
                // Novos membros são 'member' por padrão
                $this->database->addConversationMember(
                    $conversationId, 
                    $memberUser['user_id'], 
                    'member'
                );
            }
        }
        
        $conversationData = $this->database->getConversationById($conversationId);
        
        $response->setSuccess(true);
        $response->setMessage("Group created successfully");
        $response->setConversation($this->mapConversation($conversationData));
        
    } catch (\Exception $e) {
        $this->logger->error("CreateGroup error: " . $e->getMessage());
        $response->setSuccess(false);
        $response->setMessage($e->getMessage());
    }
    
    return $response;
}
```

### 4.5 Tracking de Leitura (`Database.php`)

```php
public function updateLastReadAt(string $conversationId, string $userId): void
{
    $stmt = $this->pdo->prepare('
        UPDATE conversation_members
        SET last_read_at = NOW()
        WHERE conversation_id = :conversation_id
        AND user_id = :user_id
    ');
    
    $stmt->execute([
        'conversation_id' => $conversationId,
        'user_id' => $userId
    ]);
}

// Usado para calcular unread count
public function getUnreadCount(string $conversationId, string $userId): int
{
    $stmt = $this->pdo->prepare('
        SELECT COUNT(*) as count
        FROM messages m
        JOIN conversation_members cm ON m.conversation_id = cm.conversation_id
        WHERE m.conversation_id = :conversation_id
        AND cm.user_id = :user_id
        AND m.created_at > COALESCE(cm.last_read_at, \'1970-01-01\')
        AND m.from_user_id != :user_id
    ');
    
    $stmt->execute([
        'conversation_id' => $conversationId,
        'user_id' => $userId
    ]);
    
    return (int)$stmt->fetch()['count'];
}
```

**Análise crítica**: O uso de `COALESCE` para tratar `last_read_at` NULL é elegante, mas considera todas as mensagens como não lidas para novos membros. Isso pode ser o comportamento desejado ou não, dependendo do requisito.

### 4.6 Listagem de Conversas (`ConversationService.php`)

```php
public function ListConversations(ListConversationsRequest $request): ListConversationsResponse
{
    $response = new ListConversationsResponse();
    
    try {
        $userId = $request->getUserId();
        $limit = $request->getLimit() ?: 50;
        
        $conversationsData = $this->database->getUserConversations($userId, $limit);
        
        $conversations = [];
        foreach ($conversationsData as $data) {
            $summary = new ConversationSummary();
            $summary->setConversationId($data['conversation_id']);
            $summary->setType($data['type']);
            
            // Para private: exibir nome do outro usuário
            if ($data['type'] === 'private') {
                $fullConv = $this->database->getConversationById($data['conversation_id']);
                foreach ($fullConv['members'] as $member) {
                    if ($member['user_id'] !== $userId) {
                        $summary->setName($member['username']);
                        break;
                    }
                }
            } else {
                // Para groups: usar nome do grupo
                $fullConv = $this->database->getConversationById($data['conversation_id']);
                $summary->setName($fullConv['name']);
            }
            
            $summary->setLastMessage($data['last_message_snippet'] ?? '');
            $summary->setLastMessageAt($data['last_message_at'] ?? '');
            
            $conversations[] = $summary;
        }
        
        $response->setSuccess(true);
        $response->setConversations($conversations);
        
    } catch (\Exception $e) {
        $this->logger->error("ListConversations error: " . $e->getMessage());
        $response->setSuccess(false);
    }
    
    return $response;
}
```

## 5. Análise Crítica

### 5.1 Conformidade com Requisitos

| Sub-requisito | Status | Evidência |
|---------------|--------|-----------|
| Tipo `private` | ✅ | `type CHECK ('private', 'group')` |
| Tipo `group` | ✅ | `CreateGroup` em ConversationService |
| Roles owner/admin/member | ✅ | `role CHECK ('owner', 'admin', 'member')` |
| `last_read_at` tracking | ✅ | Coluna em `conversation_members` + `updateLastReadAt()` |

### 5.2 Limitações Identificadas

#### Limitação 1: Hierarquia de Roles Não Aplicada

**Problema**: Roles são armazenados mas não verificados em operações:
```php
// Qualquer membro pode enviar mensagem, não só owner/admin
// Não há verificação: "apenas admin pode remover membros"
```

**Impacto**: Membro comum pode executar ações que deveriam ser restritas.

**Solução proposta**:
```php
public function canPerformAction(string $userId, string $conversationId, string $action): bool
{
    $role = $this->getMemberRole($userId, $conversationId);
    
    $permissions = [
        'send_message' => ['owner', 'admin', 'member'],
        'add_member' => ['owner', 'admin'],
        'remove_member' => ['owner', 'admin'],
        'change_group_name' => ['owner', 'admin'],
        'promote_to_admin' => ['owner'],
        'delete_group' => ['owner']
    ];
    
    return in_array($role, $permissions[$action] ?? []);
}
```

#### Limitação 2: Query N+1 em Listagem de Conversas

**Problema**:
```php
foreach ($conversationsData as $data) {
    // Para cada conversa, faz query adicional
    $fullConv = $this->database->getConversationById($data['conversation_id']);
}
```

**Impacto**: Com 50 conversas, são 51 queries. Latência aumenta linearmente.

**Solução proposta**: Subquery na listagem original:
```sql
SELECT c.*, 
    CASE 
        WHEN c.type = 'private' THEN (
            SELECT u.username 
            FROM users u 
            JOIN conversation_members cm2 ON u.user_id = cm2.user_id 
            WHERE cm2.conversation_id = c.conversation_id 
            AND cm2.user_id != :user_id 
            LIMIT 1
        )
        ELSE c.name
    END as display_name
FROM conversations c
JOIN conversation_members cm ON c.conversation_id = cm.conversation_id
WHERE cm.user_id = :user_id
ORDER BY c.last_message_at DESC
LIMIT :limit;
```

#### Limitação 3: Sem Paginação com Cursor

**Problema**: Listagem usa `LIMIT` simples sem cursor.

**Impacto**: 
- Páginas subsequentes podem ter items duplicados se novas conversas forem criadas
- Inconsistência em scrolling infinito

**Solução proposta**: Cursor-based pagination:
```php
public function getUserConversations(string $userId, int $limit, ?string $cursor = null): array
{
    $query = '
        SELECT * FROM conversations c
        JOIN conversation_members cm ON c.conversation_id = cm.conversation_id
        WHERE cm.user_id = :user_id
    ';
    
    if ($cursor) {
        $query .= ' AND c.last_message_at < :cursor';
    }
    
    $query .= ' ORDER BY c.last_message_at DESC LIMIT :limit';
    // ...
}
```

#### Limitação 4: Soft Delete Inconsistente

**Problema**: `is_active = false` marca conversa como inativa, mas membros ainda existem.

**Impacto**: Queries de membership retornam conversas inativas.

**Solução proposta**: Sempre filtrar por `is_active`:
```sql
WHERE c.is_active = true
```

### 5.3 Pontos Fortes

1. **Idempotência em private**: Não cria conversa duplicada entre mesmos usuários
2. **Desnormalização inteligente**: `last_message_*` acelera listagem
3. **Índices otimizados**: Queries por conversation_id e user_id são O(log n)
4. **Constraint no banco**: CHECK em type e role garante integridade
