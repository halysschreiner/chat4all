# RF06 - Controle de Status de Mensagens

---

## 1. Resumo do Requisito

> **RF06**: Acompanhar status de envio da mensagem (enviado, entregue, lido, falha) com atualização em tempo real via WebSocket.

Esta é uma das funcionalidades mais complexas em sistemas de mensageria distribuída. O desafio está em:
- **Rastreabilidade**: Cada mensagem tem seu próprio ciclo de vida
- **Consistência**: Todos os clientes devem ver o mesmo status
- **Latência**: Atualizações devem ser "instantâneas" (< 1s)

---

## 2. Arquitetura Adotada

### 2.1 Máquina de Estados

```
┌─────────────────────────────────────────────────────────────┐
│                  MÁQUINA DE ESTADOS: MENSAGEM               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   PENDING ──────▶ SENT ──────▶ DELIVERED ──────▶ READ       │
│      │             │              │               │         │
│      │             │              │               │         │
│      └─────────────┴──────────────┴───────────────┘         │
│                         │                                    │
│                         ▼                                    │
│                      FAILED                                  │
│                                                             │
│  Transições válidas:                                        │
│  • PENDING → SENT: Mensagem publicada no Kafka              │
│  • PENDING → FAILED: Erro ao publicar                       │
│  • SENT → DELIVERED: Connector confirmou entrega            │
│  • SENT → FAILED: Timeout ou erro no connector              │
│  • DELIVERED → READ: Destinatário abriu a mensagem          │
│                                                             │
│  Transições INVÁLIDAS (não podem acontecer):                │
│  • READ → DELIVERED (não pode "des-ler")                    │
│  • FAILED → SENT (precisa reenviar nova mensagem)           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 3. Implementação

### 3.1 StatusNotificationHandler.php

```php
// workers/websocket-worker/src/StatusNotificationHandler.php

/**
 * Handler de WebSocket que gerencia conexões e distribui notificações de status
 */
class StatusNotificationHandler implements MessageComponentInterface
{
    protected \SplObjectStorage $clients;
    protected array $userConnections = [];   // user_id => [conn_id, ...]
    protected array $connectionUsers = [];   // conn_id => user_id
    protected Logger $logger;

    /**
     * Processa autenticação do cliente WebSocket
     */
    public function onMessage(ConnectionInterface $from, $msg)
    {
        try {
            $data = json_decode($msg, true);
            
            if (!$data) {
                $from->send(json_encode(['error' => 'Invalid JSON']));
                return;
            }
            
            $action = $data['action'] ?? '';
            
            switch ($action) {
                case 'authenticate':
                    $this->handleAuthentication($from, $data);
                    break;
                    
                case 'mark_read':
                    $this->handleMarkAsRead($from, $data);
                    break;
                    
                default:
                    $from->send(json_encode(['error' => 'Unknown action']));
            }
        } catch (\Exception $e) {
            $this->logger->error('WebSocket message error: ' . $e->getMessage());
        }
    }

    /**
     * Autentica conexão WebSocket com token JWT
     */
    protected function handleAuthentication(ConnectionInterface $conn, array $data): void
    {
        $token = $data['token'] ?? '';
        
        if (empty($token)) {
            $conn->send(json_encode(['error' => 'Token required']));
            return;
        }
        
        // Validar JWT (simplificado - em produção, verificar assinatura)
        try {
            $payload = $this->decodeJwt($token);
            $userId = $payload['user_id'];
            
            // Mapear conexão → usuário
            $this->connectionUsers[$conn->resourceId] = $userId;
            
            // Mapear usuário → conexões (suporta multi-device)
            if (!isset($this->userConnections[$userId])) {
                $this->userConnections[$userId] = [];
            }
            $this->userConnections[$userId][] = $conn->resourceId;
            
            $conn->send(json_encode([
                'type' => 'authenticated',
                'user_id' => $userId
            ]));
            
        } catch (\Exception $e) {
            $conn->send(json_encode(['error' => 'Invalid token']));
        }
    }

    /**
     * Notifica usuário sobre atualização de status
     * Chamado pelo RedisSubscriber quando recebe evento
     */
    public function notifyUser(string $userId, array $message): void
    {
        if (!isset($this->userConnections[$userId])) {
            return;  // Usuário não conectado
        }
        
        $payload = json_encode([
            'type' => 'status_update',
            'message_id' => $message['message_id'],
            'status' => $message['status'],
            'timestamp' => $message['timestamp'] ?? time()
        ]);
        
        // Notifica TODAS as conexões do usuário (multi-device)
        foreach ($this->userConnections[$userId] as $connId) {
            foreach ($this->clients as $client) {
                if ($client->resourceId === $connId) {
                    $client->send($payload);
                    break;
                }
            }
        }
    }
}
```

### 3.2 MessageProcessor.php - Callback de Status

```php
// connectors/whatsapp-mock/src/MessageProcessor.php

/**
 * Processa mensagens do Kafka e simula entrega via WhatsApp
 */
class MessageProcessor
{
    /**
     * Processa uma mensagem recebida do Kafka
     */
    public function process(array $message): void
    {
        $messageId = $message['message_id'];
        $this->logger->info("Processing message: {$messageId}");
        
        try {
            // Simular processamento (em produção, enviaria para WhatsApp API)
            $this->simulateDelivery($message);
            
            // Enviar callback de status SENT
            $this->sendStatusCallback($messageId, 'SENT');
            
            // Simular delay de entrega
            usleep(500000);  // 500ms
            
            // Enviar callback de status DELIVERED
            $this->sendStatusCallback($messageId, 'DELIVERED');
            
        } catch (\Exception $e) {
            $this->logger->error("Failed to process message: {$e->getMessage()}");
            $this->sendStatusCallback($messageId, 'FAILED');
        }
    }

    /**
     * Envia callback para API Service com novo status
     */
    protected function sendStatusCallback(string $messageId, string $status): void
    {
        $callbackUrl = getenv('BACKEND_CALLBACK_URL');
        
        $payload = json_encode([
            'message_id' => $messageId,
            'status' => $status,
            'timestamp' => time(),
            'platform' => 'whatsapp'
        ]);
        
        $ch = curl_init($callbackUrl);
        curl_setopt_array($ch, [
            CURLOPT_POST => true,
            CURLOPT_POSTFIELDS => $payload,
            CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT => 5
        ]);
        
        $response = curl_exec($ch);
        $httpCode = curl_getinfo($ch, CURLINFO_HTTP_CODE);
        curl_close($ch);
        
        if ($httpCode !== 200) {
            $this->logger->warning("Callback failed with code {$httpCode}");
        }
    }
}
```

### 3.4 RedisSubscriber.php

```php
// workers/websocket-worker/src/RedisSubscriber.php

/**
 * Subscreve a canal Redis e repassa eventos para o WebSocket handler
 */
class RedisSubscriber
{
    public function __construct(
        private string $host,
        private int $port,
        private StatusNotificationHandler $wsHandler,
        private Logger $logger,
        private LoopInterface $loop
    ) {}

    /**
     * Inicia subscrição ao canal de status updates
     */
    public function subscribe(): void
    {
        $factory = new \Clue\React\Redis\Factory($this->loop);
        
        $factory->createClient("redis://{$this->host}:{$this->port}")
            ->then(function ($client) {
                $this->logger->info('Connected to Redis for Pub/Sub');
                
                // Subscrever ao canal de status updates
                $client->subscribe('status-updates');
                
                $client->on('message', function ($channel, $message) {
                    $this->handleStatusUpdate($message);
                });
            });
    }

    /**
     * Processa atualização de status recebida do Redis
     */
    protected function handleStatusUpdate(string $message): void
    {
        $data = json_decode($message, true);
        
        if (!$data || !isset($data['message_id'])) {
            return;
        }
        
        // Buscar remetente da mensagem para notificar
        $userId = $this->getSenderUserId($data['message_id']);
        
        if ($userId) {
            $this->wsHandler->notifyUser($userId, $data);
        }
    }
}
```

## 4. Análise Crítica

### 4.1 Conformidade com o Requisito

| Aspecto | Status | Evidência |
|---------|--------|-----------|
| Status PENDING | ✅ | Default no INSERT |
| Status SENT | ✅ | Callback do connector |
| Status DELIVERED | ✅ | Callback do connector |
| Status READ | ✅ | Endpoint mark_read |
| Status FAILED | ✅ | Callback em caso de erro |
| WebSocket real-time | ✅ | Redis Pub/Sub → WebSocket |

### 4.2 Pontos Fortes

1. **Desacoplamento via Redis Pub/Sub**: API Service não conhece WebSocket workers
2. **Multi-device**: Usuário pode ter várias conexões, todas recebem update
3. **Estado centralizado**: PostgreSQL é fonte de verdade

### 4.3 Limitações Identificadas

#### Limitação 1: Sem Validação de Transição de Estado

**Problema**: Código não valida se transição é válida.

```php
// Aceita qualquer status sem verificar estado atual
$request->setStatus($status);  // READ → PENDING seria aceito!
```

**Solução**:
```php
$validTransitions = [
    'PENDING' => ['SENT', 'FAILED'],
    'SENT' => ['DELIVERED', 'FAILED'],
    'DELIVERED' => ['READ'],
    'READ' => [],
    'FAILED' => []
];

$currentStatus = getCurrentStatus($messageId);
if (!in_array($newStatus, $validTransitions[$currentStatus])) {
    throw new InvalidStateTransition("Cannot transition from {$currentStatus} to {$newStatus}");
}
```

#### Limitação 2: WebSocket Worker Não Escalável

**Problema**: Estado de conexões está em memória local.

```php
protected array $userConnections = [];  // Perdido se worker reiniciar!
```

**Solução**: Armazenar mapeamento no Redis:
```php
// Em vez de array local
$this->redis->sAdd("ws:user:{$userId}", $connId);
$this->redis->set("ws:conn:{$connId}", $userId);
```

#### Limitação 3: Sem Retry em Callback Falho

**Problema**: Se callback falha, status fica inconsistente.

```php
if ($httpCode !== 200) {
    $this->logger->warning("Callback failed");  // E daí? Mensagem fica PENDING?
}
```

**Solução**: Dead letter queue ou retry com exponential backoff.

#### Limitação 4: Latência de READ

**Problema**: Usuário precisa clicar/abrir para marcar como lido.

**Solução**: Marcar automaticamente quando conversa está aberta:
```typescript
// Frontend: quando conversa está visível
if (document.visibilityState === 'visible' && selectedConversation === msg.conversation_id) {
    markAsRead(msg.message_id);
}
```
