# RF07 - Connectors Mock (Integração Multiplataforma)

---

## 1. Resumo do Requisito

> **RF07**: Criar serviços `connector_whatsapp_mock` e `connector_instagram_mock`.
> Cada connector deve:
> - Receber mensagens de um tópico Kafka específico (`whatsapp.messages`, `instagram.messages`).
> - Simular envio com logs (ex: `[WhatsApp] Entregue a usuário X`).
> - Retornar callback simulando entrega/leitura.
> 
> Implementar endpoints nos connectors:
> - `GET /health` - Health check.
> - `POST /send` - Simular envio manual de mensagem.
> - `POST /webhook/incoming` - Receber mensagens simuladas do canal externo.

### Dependências com Outros Requisitos

| Requisito | Tipo de Dependência | Descrição |
|-----------|---------------------|-----------|
| **RF06** | Contrato de Status | Connectors emitem callbacks com status definidos em RF06 (SENT, DELIVERED, READ, FAILED) |
| **RF08** | Evento Downstream | Callbacks dos connectors disparam notificações WebSocket |
| **RNF04** | Infraestrutura | Connectors consomem mensagens via Apache Kafka |

### Conceito Teórico

Os connectors implementam o **Adapter Pattern** (GoF), atuando como ponte entre o sistema interno e plataformas externas. Em produção, seriam integrações reais com APIs do WhatsApp Business e Instagram Graph API. No contexto acadêmico, simulam o comportamento esperado dessas APIs.

**Princípio aplicado**: *Dependency Inversion* - O sistema depende de abstrações (interface de connector), não de implementações concretas (WhatsApp/Instagram).

## 3. Stack Tecnológica

| Componente | Tecnologia | Justificativa |
|------------|------------|---------------|
| **Runtime** | PHP 8.2 | Consistência com stack do projeto |
| **Kafka Client** | php-rdkafka | Binding oficial librdkafka, baixa latência |
| **HTTP Client** | Guzzle | Padrão de mercado para callbacks |
| **Logging** | Monolog | Logs estruturados com contexto |

### Trade-off Considerado

**Alternativa**: Go ou Rust para connectors de alta performance.

**Decisão**: PHP mantido por:
1. Menor curva de aprendizado para equipe
2. Mocks não exigem performance extrema
3. Facilita debug com stack homogênea

**Risco aceito**: Throughput limitado em cenários de produção real.

### 4.2 Consumer Kafka (`consumer.php`)

<?php
require_once __DIR__ . '/vendor/autoload.php';

use Chat4All\Connector\WhatsApp\KafkaConsumer;

$logger = new Logger('whatsapp-connector');

$kafkaConfig = [
    'bootstrap_servers' => getenv('KAFKA_BROKER') ?: 'kafka:9092',
    'group_id' => 'whatsapp-connector-group',
    'topic' => 'whatsapp.messages'

$processor = new MessageProcessor($logger);

**Análise crítica**:
- `group_id` fixo permite escalabilidade horizontal via Consumer Group
- Tópico dedicado (`whatsapp.messages`) evita competição com outros consumers

### 4.3 Message Processor (`MessageProcessor.php`)

```php
public function process(string $payload): void
{
    $data = json_decode($payload, true);
    
    $messageId = $data['message_id'] ?? null;
    $to = $data['to'] ?? 'unknown';
    $text = $data['text'] ?? '';
    $fileId = $data['file_id'] ?? null;

    // Log de recebimento
    $this->logger->info('[WhatsApp] 📥 Mensagem recebida do Kafka', [
        'message_id' => $messageId,
        'to' => $to,
        'has_file' => $fileId !== null
    ]);

    // Simular falha aleatória se configurado
    if ($this->shouldSimulateFailure()) {
        $this->handleFailure($messageId, $to);
        return;
    }

    // Simular processamento e envio
    $this->simulateSending($messageId, $to, $text, $fileId);

    // Enviar callbacks de status
    $this->sendDeliveryCallbacks($messageId, $to);
}

private function simulateSending(string $messageId, string $to, string $text, ?string $fileId): void
{
    // Simular delay de envio (50-200ms)
    usleep(rand(50000, 200000));

    $this->logger->info("[WhatsApp] ✅ Mensagem enviada para {$to}", [
        'message_id' => $messageId
    ]);

    // Callback SENT imediato
    $this->callbackSender->send($messageId, 'SENT', [
        'recipient' => $to,
        'has_attachment' => $fileId !== null
    ]);
}

private function sendDeliveryCallbacks(string $messageId, string $to): void
{
    // DELIVERED após 1-3 segundos
    $this->callbackSender->sendDeliveredWithDelay(
        $messageId,
        $this->deliveryMinDelay,  // 1s
        $this->deliveryMaxDelay   // 3s
    );

    $this->logger->info("[WhatsApp] 📬 Callback DELIVERED enviado", [
        'message_id' => $messageId
    ]);

    // READ após 3-8 segundos
    $this->callbackSender->sendReadWithDelay(
        $messageId,
        $this->readMinDelay,  // 3s
        $this->readMaxDelay   // 8s
    );

    $this->logger->info("[WhatsApp] 👁️ Callback READ enviado", [
        'message_id' => $messageId
    ]);
}
```

### 4.4 Simulação de Falhas

```php
private function handleFailure(string $messageId, string $to): void
{
    $errorCodes = [
        'RECIPIENT_NOT_FOUND' => 'Destinatário não encontrado no WhatsApp',
        'RATE_LIMITED' => 'Taxa de envio excedida',
        'NETWORK_ERROR' => 'Erro de rede ao conectar com WhatsApp',
        'MEDIA_TOO_LARGE' => 'Arquivo muito grande para envio'
    ];

    $errorCode = array_rand($errorCodes);
    $errorMessage = $errorCodes[$errorCode];

    $this->logger->warning("[WhatsApp] ⚠️ Falha simulada", [
        'message_id' => $messageId,
        'error_code' => $errorCode
    ]);

    $this->callbackSender->sendFailed($messageId, $errorCode, $errorMessage);
}
```

**Conceito teórico**: Simulação de falhas implementa *Chaos Engineering* em escala reduzida, permitindo testar resiliência do sistema.

### 4.5 Callback Sender

```php
class CallbackSender
{
    private string $backendUrl;
    
    public function send(string $messageId, string $status, array $metadata = []): void
    {
        $payload = [
            'message_id' => $messageId,
            'status' => $status,
            'platform' => 'whatsapp',
            'timestamp' => date('c'),
            'metadata' => $metadata
        ];
        
        // POST para o backend
        $this->httpClient->post($this->backendUrl, [
            'json' => $payload
        ]);
    }
    
    public function sendDeliveredWithDelay(string $messageId, int $minDelay, int $maxDelay): void
    {
        sleep(rand($minDelay, $maxDelay));
        $this->send($messageId, 'DELIVERED');
    }
}
```

| `POST /webhook/incoming` | ✅ | Simulação de mensagem externa |

### 6.2 Limitações Identificadas

#### Limitação 1: Callbacks Síncronos Bloqueantes

**Problema**:
```php
public function sendDeliveredWithDelay(...): void
{
    sleep(rand($minDelay, $maxDelay)); // BLOQUEANTE!
    $this->send(...);
}
```

**Impacto**: 
- Throughput limitado: 1 mensagem processada por vez durante delays
- Se delay médio = 2s, máximo = 30 msg/minuto por instância

**Solução proposta**: Usar timers assíncronos com ReactPHP:
```php
$loop->addTimer($delay, function() use ($messageId) {
    $this->send($messageId, 'DELIVERED');
});
```

#### Limitação 2: Sem Retry em Callbacks

**Problema**: Se API Service está indisponível, callback falha silenciosamente.

**Impacto**: Mensagem fica em status SENT indefinidamente.

**Solução proposta**: Implementar retry com exponential backoff:
```php
$retryDelays = [1, 2, 4, 8, 16]; // segundos
foreach ($retryDelays as $delay) {
    try {
        $this->httpClient->post($url, $payload);
        return; // Sucesso
    } catch (Exception $e) {
        sleep($delay);
    }
}
// Dead letter queue após falhas
```

#### Limitação 3: Sem Idempotência em Callbacks

**Problema**: Se callback é enviado 2x (network retry), mensagem pode ter status atualizado incorretamente.

**Impacto**: Inconsistência de estado.

**Solução proposta**: Incluir `idempotency_key` no callback:
```php
$payload = [
    'message_id' => $messageId,
    'status' => $status,
    'idempotency_key' => hash('sha256', $messageId . $status . $timestamp)
];
```

### 6.3 Pontos Fortes

1. **Isolamento por plataforma**: Cada connector é independente, falha não cascateia
2. **Consumer Group**: Escalabilidade horizontal via Kafka
3. **Simulação configurável**: Delays e falhas ajustáveis por variáveis de ambiente
4. **Logs estruturados**: Facilitam debug com emojis visuais

## 7. Configuração

### 7.1 Variáveis de Ambiente

| Variável | Padrão | Descrição |
|----------|--------|-----------|
| `KAFKA_BROKER` | `kafka:9092` | Endereço do broker Kafka |
| `KAFKA_GROUP_ID` | `whatsapp-connector-group` | Consumer group |
| `BACKEND_CALLBACK_URL` | `http://api-service:8080/v1/callbacks/whatsapp` | URL para callbacks |
| `DELIVERY_MIN_DELAY` | `1` | Delay mínimo para DELIVERED (segundos) |
| `DELIVERY_MAX_DELAY` | `3` | Delay máximo para DELIVERED (segundos) |
| `READ_MIN_DELAY` | `3` | Delay mínimo para READ (segundos) |
| `READ_MAX_DELAY` | `8` | Delay máximo para READ (segundos) |
| `FAILURE_RATE` | `0.05` | Taxa de falha simulada (5%) |

whatsapp-connector:

## 9. Referências Teóricas

- **Adapter Pattern** (GoF): Connectors como adaptadores entre sistemas
