# RF05 - Envio de Arquivos: Análise de Implementação

---

## 1. Resumo do Requisito

### Transcrição do RF05

> **RF05 - Envio de Arquivos**
> - O sistema deve permitir o envio de arquivos (texto, imagem, PDF, vídeo, áudio).
> - Suporte a arquivos de até 2GB.
> - Implementar upload multipart (resumable).
> - Endpoints:
>   - `POST /v1/files/upload/initiate` - Iniciar upload multipart.
>   - `POST /v1/files/upload/part` - Enviar cada parte do arquivo.
>   - `POST /v1/files/upload/complete` - Completar upload.
>   - `GET /v1/files/{id}/download` - Obter URL temporária de download (presigned URL válida por 1 hora).
> - Registrar metadados no banco: file_id, checksum, tamanho (file_size), uploader (user_id), conversation_id.
> - API `POST /v1/messages` deve aceitar payload com `type: "file"` e `file_id`.

### Importância no Contexto do Sistema

RF05 transforma o Chat4All de um sistema de texto para uma **plataforma de comunicação multimídia**. O suporte a 2GB exige arquitetura específica:

1. **Upload Multipart**: Arquivos grandes divididos em chunks de 5MB
2. **Resumable**: Se conexão cair, retoma do último chunk enviado
3. **Presigned URLs**: Download direto do Object Storage sem passar pelo backend

**Conceito teórico**: O padrão implementado é **S3 Multipart Upload** (AWS), que divide arquivos em partes de 5MB-5GB, permitindo upload paralelo e retomada.

## 2. Solução Arquitetural

### 2.1 Arquitetura de Upload

```
┌─────────────────┐                          ┌────────────────────┐
│   Frontend      │  1. initiate (metadata)  │   API Service      │
│   (Angular)     │ ─────────────────────────▶│   (FileController) │
│                 │                          │                    │
│                 │  2. upload_id + part_size │                    │
│                 │ ◀─────────────────────────│                    │
│                 │                          └─────────┬──────────┘
│                 │                                    │
│                 │  3. PUT parts (5MB each)           │ MinIO API
│                 │ ───────────────────────────────────┼─────────────▶ ┌────────────┐
│                 │                                    │               │   MinIO    │
│                 │  4. complete                       │               │   (S3)     │
│                 │ ─────────────────────────────────▶ │               │            │
│                 │                                    │ Complete      │            │
│                 │                                    │ ─────────────▶│            │
│                 │  5. file_id                        │               └────────────┘
│                 │ ◀──────────────────────────────────│
│                 │                                    │
│                 │  6. POST /messages (type:file)     │
│                 │ ─────────────────────────────────▶ │
└─────────────────┘                                    ▼
                                              ┌────────────────────┐
                                              │   PostgreSQL       │
                                              │   (file metadata)  │
                                              └────────────────────┘
```

### 2.2 Fluxo Detalhado

1. **Initiate**: Cliente envia metadados (nome, tamanho, tipo). Backend retorna `upload_id` e número de partes.
2. **Upload Parts**: Cliente envia cada parte de 5MB com `part_number`. MinIO armazena temporariamente.
3. **Complete**: Cliente sinaliza fim. Backend manda MinIO montar o arquivo final.
4. **Associate**: Cliente cria mensagem com `type: "file"` e `file_id`.
5. **Download**: Destinatário solicita presigned URL (válida por 1 hora).

### 2.3 Trade-offs da Arquitetura

| Decisão | Trade-off |
|---------|-----------|
| **Parts de 5MB** | (+) Retry granular, (-) Overhead de N requisições |
| **MinIO (S3-compatible)** | (+) API padrão, Presigned URLs, (-) Dependência adicional |
| **Metadados no PostgreSQL** | (+) JOIN com mensagens, (-) Sincronização com MinIO |

### 2.4 Alternativas Descartadas

#### Alternativa 1: Upload direto ao PostgreSQL (BLOB)

**Por que descartada**: 
- PostgreSQL não foi projetado para arquivos grandes
- Backup/restore ficaria lento
- Sem suporte a presigned URLs

#### Alternativa 2: Upload simples (sem multipart)

**Por que descartada**:
- Timeout em conexões lentas
- 2GB em request único = 10+ minutos
- Sem possibilidade de retomar

### 3.1 MinIO

**Por que MinIO e não AWS S3?**

| MinIO | AWS S3 |
|-------|--------|
| Self-hosted | Cloud vendor |
| Zero custo | Pay-per-use |
| Latência local | Latência WAN |
| Mesmo API S3 | API nativa S3 |

**Trade-offs**:
| Ganho | Limitação |
|-------|-----------|
| Controle total | Responsabilidade operacional |
| Sem egress costs | Sem CDN global |
| Presigned URLs | Sem Lambda@Edge |

### 3.2 AWS SDK para PHP

**Por que usar SDK da AWS para MinIO?**

MinIO implementa a API S3 100%, então o SDK oficial funciona diretamente:
```php
$this->client = new S3Client([
    'version' => 'latest',
    'region' => 'us-east-1',
    'endpoint' => 'http://minio:9000',
    'use_path_style_endpoint' => true, // Necessário para MinIO
    'credentials' => [
        'key' => $accessKey,
        'secret' => $secretKey,
    ],
]);
```

#### 4.2.1 Initiate Upload (`FileController.php`)

**Linhas 46-130**:
```php
public function initiateUpload(Request $request, Response $response): Response
{
    try {
        $userId = $request->getAttribute('user_id');
        $data = $request->getParsedBody();

        $conversationId = $data['conversation_id'];
        $filename = $data['filename'];
        $fileSize = (int)$data['file_size'];
        $contentType = $data['content_type'] ?? 'application/octet-stream';
        $checksum = $data['checksum'] ?? null;

        // Validar tamanho máximo: 2GB
        if ($fileSize > self::MAX_FILE_SIZE) {
            return $this->errorResponse($response, 'Arquivo muito grande. Máximo: 2GB', 400);
        }

        // Verificar permissão na conversa
        if (!$this->database->isUserInConversation($userId, $conversationId)) {
            return $this->errorResponse($response, 'Usuário não pertence a esta conversa', 403);
        }

        // Gerar IDs únicos
        $fileId = $this->generateUuid();
        $uploadId = $this->generateUuid();
        
        // Calcular número de partes (5MB cada)
        $totalParts = (int)ceil($fileSize / self::PART_SIZE);

        // Path no MinIO: {conversation_id}/{file_id}/{filename}
        $storagePath = sprintf('%s/%s/%s', $conversationId, $fileId, $sanitizedFilename);

        // Salvar metadados no banco com status 'uploading'
        $fileData = [
            'file_id' => $fileId,
            'upload_id' => $uploadId,
            'conversation_id' => $conversationId,
            'user_id' => $userId,
            'filename' => $sanitizedFilename,
            'file_size' => $fileSize,
            'content_type' => $contentType,
            'storage_path' => $storagePath,
            'checksum' => $checksum,
            'status' => 'uploading',
            'total_parts' => $totalParts,
            'uploaded_parts' => 0
        ];

        $this->database->insertFile($fileData);

        // Iniciar multipart no MinIO
        $minioUploadId = $this->minioService->initiateMultipartUpload($storagePath, $contentType);
        $this->database->updateFileMinioUploadId($fileId, $minioUploadId);

        return $this->jsonResponse($response, [
            'success' => true,
            'upload_id' => $uploadId,
            'file_id' => $fileId,
            'part_size' => self::PART_SIZE,
            'total_parts' => $totalParts
        ]);
    }
    // ...
}
```

**Constantes importantes**:
```php
private const MAX_FILE_SIZE = 2 * 1024 * 1024 * 1024; // 2GB
private const PART_SIZE = 5 * 1024 * 1024;            // 5MB por parte
```

#### 4.2.2 Upload Part (`FileController.php`)

**Linhas 158-245**:
```php
public function uploadPart(Request $request, Response $response): Response
{
    try {
        $userId = $request->getAttribute('user_id');
        $params = $request->getParsedBody();
        $uploadedFiles = $request->getUploadedFiles();

        $uploadId = $params['upload_id'];
        $fileId = $params['file_id'];
        $partNumber = (int)$params['part_number'];

        // Validar propriedade do arquivo
        $fileInfo = $this->database->getFileById($fileId);
        
        if ($fileInfo['user_id'] !== $userId) {
            return $this->errorResponse($response, 'Sem permissão', 403);
        }

        if ($fileInfo['status'] !== 'uploading') {
            return $this->errorResponse($response, 'Upload não em progresso', 400);
        }

        // Suporta multipart/form-data OU JSON base64
        $partData = null;
        if (isset($uploadedFiles['data'])) {
            $partData = $uploadedFiles['data']->getStream()->getContents();
        } elseif (isset($params['data'])) {
            $partData = base64_decode($params['data']);
        }

        // Upload da parte para MinIO
        $etag = $this->minioService->uploadPart(
            $fileInfo['storage_path'],
            $fileInfo['minio_upload_id'],
            $partNumber,
            $partData
        );

        // Registrar parte no banco
        $this->database->insertFilePart($fileId, $partNumber, $etag, strlen($partData));
        $this->database->incrementFileUploadedParts($fileId);

        return $this->jsonResponse($response, [
            'success' => true,
            'part_number' => $partNumber,
            'etag' => $etag,
            'bytes_uploaded' => strlen($partData)
        ]);
    }
    // ...
}
```

**ETag**: MinIO retorna um hash MD5 de cada parte, usado para verificar integridade na montagem final.

#### 4.2.3 Complete Upload (`FileController.php`)

**Linhas 263-320**:
```php
public function completeUpload(Request $request, Response $response): Response
{
    try {
        $fileId = $data['file_id'];
        $fileInfo = $this->database->getFileById($fileId);

        // Verificar se todas as partes foram enviadas
        $parts = $this->database->getFileParts($fileId);
        
        if (count($parts) !== $fileInfo['total_parts']) {
            return $this->errorResponse($response, 'Upload incompleto', 400);
        }

        // Manda MinIO montar o arquivo final
        $this->minioService->completeMultipartUpload(
            $fileInfo['storage_path'],
            $fileInfo['minio_upload_id'],
            $parts  // Array com part_number + etag
        );

        // Atualizar status no banco
        $this->database->updateFileStatus($fileId, 'completed');

        // Log de auditoria
        $this->database->insertAuditLog(
            'file.uploaded',
            'file',
            $fileId,
            $userId,
            ['conversation_id' => $fileInfo['conversation_id']]
        );

        return $this->jsonResponse($response, [
            'success' => true,
            'file_info' => [
                'file_id' => $fileId,
                'filename' => $fileInfo['filename'],
                'file_size' => $fileInfo['file_size'],
                'status' => 'completed'
            ]
        ]);
    }
}
```

#### 4.2.4 MinIO Service (`MinioService.php`)

**Linhas 66-140**:
```php
public function initiateMultipartUpload(string $key, string $contentType): string
{
    $result = $this->client->createMultipartUpload([
        'Bucket' => $this->bucket,
        'Key' => $key,
        'ContentType' => $contentType,
    ]);

    return $result['UploadId'];
}

public function uploadPart(string $key, string $uploadId, int $partNumber, string $data): string
{
    $result = $this->client->uploadPart([
        'Bucket' => $this->bucket,
        'Key' => $key,
        'UploadId' => $uploadId,
        'PartNumber' => $partNumber,
        'Body' => $data,
    ]);

    return $result['ETag'];
}

public function completeMultipartUpload(string $key, string $uploadId, array $parts): void
{
    // Formatar partes para S3 API
    $formattedParts = [];
    foreach ($parts as $part) {
        $formattedParts[] = [
            'PartNumber' => $part['part_number'],
            'ETag' => $part['etag'],
        ];
    }

    // Ordenar por número (obrigatório pela API S3)
    usort($formattedParts, fn($a, $b) => $a['PartNumber'] - $b['PartNumber']);

    $this->client->completeMultipartUpload([
        'Bucket' => $this->bucket,
        'Key' => $key,
        'UploadId' => $uploadId,
        'MultipartUpload' => ['Parts' => $formattedParts],
    ]);
}
```

#### 4.2.5 Presigned URL para Download

**MinioService.php**:
```php
public function getPresignedUrl(string $key, int $expiration = 3600): string
{
    $cmd = $this->client->getCommand('GetObject', [
        'Bucket' => $this->bucket,
        'Key' => $key,
    ]);

    $request = $this->client->createPresignedRequest($cmd, "+{$expiration} seconds");
    
    return (string) $request->getUri();
}
```

**Segurança**: URL contém assinatura HMAC que expira após 1 hora. Não precisa de autenticação para download.

CREATE TABLE IF NOT EXISTS files (
    file_id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    upload_id UUID NOT NULL,
    conversation_id UUID NOT NULL REFERENCES conversations(conversation_id),
    user_id UUID NOT NULL REFERENCES users(user_id),

    original_filename VARCHAR(255) NOT NULL,
    file_size BIGINT NOT NULL,
    content_type VARCHAR(100) NOT NULL,
    storage_path TEXT NOT NULL,
    checksum VARCHAR(64),

        CHECK (status IN ('uploading', 'completed', 'failed', 'aborted', 'deleted')),
    minio_upload_id TEXT,
    total_parts INT NOT NULL,
    uploaded_parts INT NOT NULL DEFAULT 0,
    
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE IF NOT EXISTS file_parts (
    file_id UUID NOT NULL REFERENCES files(file_id) ON DELETE CASCADE,
    part_number INT NOT NULL,
    etag VARCHAR(255) NOT NULL,
    bytes_uploaded BIGINT NOT NULL,
    uploaded_at TIMESTAMP DEFAULT NOW(),
    
    PRIMARY KEY (file_id, part_number)
);

## 5. Análise Crítica

### 5.1 Conformidade com Requisitos

| Sub-requisito | Status | Evidência |
|---------------|--------|-----------|
| Tipos de arquivo (texto, imagem, PDF, vídeo, áudio) | ✅ | `content_type` armazenado, sem restrição |
| Suporte até 2GB | ✅ | `MAX_FILE_SIZE = 2 * 1024 * 1024 * 1024` |
| Upload multipart resumable | ✅ | `initiateUpload`, `uploadPart`, `completeUpload` |
| POST /v1/files/upload/initiate | ✅ | `FileController::initiateUpload` |
| POST /v1/files/upload/part | ✅ | `FileController::uploadPart` |
| POST /v1/files/upload/complete | ✅ | `FileController::completeUpload` |
| GET /v1/files/{id}/download (presigned URL) | ✅ | `MinioService::getPresignedUrl` |
| Metadados no banco | ✅ | Tabela `files` com todos campos |
| Mensagem type: "file" | ✅ | `MessageService` aceita `file_id` |

### 5.2 Limitações Identificadas

#### Limitação 1: Sem Validação de Content-Type Real

**Problema**: O `content_type` é fornecido pelo cliente, não validado.

**Impacto**: Usuário pode fazer upload de `.exe` alegando ser `image/png`.

**Solução**:
```php
// Usar finfo para detectar MIME real
$finfo = new \finfo(FILEINFO_MIME_TYPE);
$realMime = $finfo->buffer($partData);
if ($realMime !== $declaredMime) {
    throw new \Exception('Content-Type mismatch');
}
```

#### Limitação 2: Sem Verificação de Checksum

**Problema**: Campo `checksum` é armazenado mas nunca verificado.

**Impacto**: Corrupção de arquivo não detectada.

**Solução**:
```php
// Após complete, verificar checksum
$finalChecksum = $this->minioService->getObjectChecksum($storagePath);
if ($finalChecksum !== $fileInfo['checksum']) {
    $this->abortUpload($fileId);
    throw new \Exception('Checksum mismatch');
}
```

#### Limitação 3: Cleanup de Uploads Abandonados

**Problema**: Se cliente inicia upload mas nunca completa, partes ficam no MinIO.

**Impacto**: Desperdício de storage.

**Solução**: Job periódico:
```php
// Cron job: Abortar uploads > 24h sem atividade
$abandonedUploads = $this->database->getAbandonedUploads(24 * 3600);
foreach ($abandonedUploads as $upload) {
    $this->minioService->abortMultipartUpload($upload['storage_path'], $upload['minio_upload_id']);
    $this->database->updateFileStatus($upload['file_id'], 'aborted');
}
```

### 5.3 Pontos Fortes

1. **Resumable**: Retry de partes individuais sem reiniciar upload
2. **Presigned URLs**: Download direto, sem sobrecarregar backend
3. **Audit trail**: Log de auditoria em `file.uploaded`
4. **Flexibilidade de encoding**: Suporta multipart/form-data e base64 JSON
