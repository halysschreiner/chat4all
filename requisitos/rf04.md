# RF04 - Criação de Grupos

---

## 1. Resumo do Requisito

> **RF04**: Criar grupo de contatos para enviar mensagens em broadcast.

Grupos introduzem complexidades adicionais:
- **Fan-out**: Uma mensagem vai para N destinatários
- **Membership**: Quem pode entrar, sair, administrar
- **Permissões**: Quem pode enviar, quem só lê

---

### 2.2 Fluxo de Criação de Grupo

```
┌─────────────────────────────────────────────────────────────┐
│                 FLUXO: CRIAR GRUPO                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. Cliente envia request                                   │
│     POST /v1/conversations/group                            │
│     {                                                       │
│       "name": "DevOps Team",                               │
│       "created_by": "user-1",                              │
│       "member_ids": ["user-2", "user-3"]                   │
│     }                                                       │
│                                                             │
│  2. API Service processa                                    │
│     ┌─────────────────────────────────────────────┐        │
│     │ BEGIN TRANSACTION                           │        │
│     │                                             │        │
│     │ INSERT INTO conversations (type='group')   │        │
│     │ INSERT INTO conversation_members (admin)    │        │
│     │ INSERT INTO conversation_members (member)   │ x N    │
│     │                                             │        │
│     │ COMMIT                                      │        │
│     └─────────────────────────────────────────────┘        │
│                                                             │
│  3. Notifica membros via Kafka                             │
│     Topic: notifications                                    │
│     {                                                       │
│       "type": "group_created",                             │
│       "conversation_id": "abc-123",                        │
│       "members": ["user-1", "user-2", "user-3"]           │
│     }                                                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 Por Que Esta Arquitetura?

| Decisão | Justificativa |
|---------|---------------|
| **Transação atômica** | Grupo não existe sem ao menos o criador como membro |
| **Role diferenciado** | `admin` pode remover membros, `member` não |
| **Notificação assíncrona** | Não bloqueia criação se push falhar |

## 3. Implementação

### 3.1 ConversationService.php - Criação de Grupo

```php
// services/api-service/src/Grpc/ConversationService.php

/**
 * Cria um grupo de conversa com múltiplos membros
 * 
 * WHY TRANSACTION: Garante atomicidade - grupo sem membros é inconsistente
 * WHY ROLE: Criador automaticamente é admin para gerenciar o grupo
 */
public function CreateGroup(
    Conversation\CreateGroupRequest $request,
    ServerContext $context
): Conversation\CreateConversationResponse {
    $response = new Conversation\CreateConversationResponse();
    
    try {
        $groupName = $request->getName();
        $createdBy = $request->getCreatedBy();
        $memberIds = iterator_to_array($request->getMemberIds());
        
        // Garante que criador está na lista de membros
        if (!in_array($createdBy, $memberIds)) {
            $memberIds[] = $createdBy;
        }
        
        // Gerar UUID para o grupo
        $conversationId = $this->generateUuid();
        
        // === INÍCIO DA TRANSAÇÃO ===
        $this->database->beginTransaction();
        
        try {
            // 1. Criar a conversa do tipo grupo
            $query = "INSERT INTO conversations (conversation_id, type, name, created_by, created_at) 
                      VALUES (:id, 'group', :name, :created_by, NOW())";
            
            $this->database->execute($query, [
                ':id' => $conversationId,
                ':name' => $groupName,
                ':created_by' => $createdBy
            ]);
            
            // 2. Adicionar membros
            foreach ($memberIds as $memberId) {
                // Criador é admin, outros são members
                $role = ($memberId === $createdBy) ? 'admin' : 'member';
                
                $memberQuery = "INSERT INTO conversation_members (conversation_id, user_id, role, joined_at) 
                               VALUES (:conv_id, :user_id, :role, NOW())";
                
                $this->database->execute($memberQuery, [
                    ':conv_id' => $conversationId,
                    ':user_id' => $memberId,
                    ':role' => $role
                ]);
            }
            
            // 3. Commit da transação
            $this->database->commit();
            
            // 4. Audit log (fora da transação)
            $this->insertAuditLog($createdBy, 'group_created', [
                'conversation_id' => $conversationId,
                'group_name' => $groupName,
                'member_count' => count($memberIds)
            ]);
            
            // 5. Notificar membros via Kafka (assíncrono)
            $this->kafkaProducer->publish([
                'type' => 'group_created',
                'conversation_id' => $conversationId,
                'group_name' => $groupName,
                'members' => $memberIds
            ], $conversationId);
            
            $response->setSuccess(true);
            $response->setConversationId($conversationId);
            $response->setMessage('Group created successfully');
            
        } catch (\Exception $e) {
            $this->database->rollback();
            throw $e;
        }
        
    } catch (\Exception $e) {
        $this->logger->error('Failed to create group: ' . $e->getMessage());
        $response->setSuccess(false);
        $response->setMessage('Failed to create group: ' . $e->getMessage());
    }
    
    return $response;
}
```

### 3.2 Envio de Mensagem para Grupo (Fan-out)

```php
// Quando uma mensagem é enviada para um grupo, o router-worker
// precisa notificar todos os membros

// workers/router-worker/src/MessageProcessor.php
public function processGroupMessage(array $message): void
{
    $conversationId = $message['conversation_id'];
    
    // Buscar todos os membros do grupo
    $members = $this->database->fetchAll(
        "SELECT user_id FROM conversation_members WHERE conversation_id = :id",
        [':id' => $conversationId]
    );
    
    // Fan-out: notificar cada membro
    foreach ($members as $member) {
        // Publicar notificação individual
        $this->redis->publish("status:user:{$member['user_id']}", json_encode([
            'type' => 'new_message',
            'conversation_id' => $conversationId,
            'message_id' => $message['message_id'],
            'from_user_id' => $message['from_user_id']
        ]));
    }
}
```

### 3.3 Listagem de Conversas (Incluindo Grupos)

```php
/**
 * Lista todas as conversas de um usuário
 * Inclui tanto privadas quanto grupos
 */
public function ListConversations(
    Conversation\ListConversationsRequest $request,
    ServerContext $context
): Conversation\ListConversationsResponse {
    $response = new Conversation\ListConversationsResponse();
    
    try {
        $userId = $request->getUserId();
        $limit = $request->getLimit() ?: 50;
        $offset = $request->getOffset() ?: 0;
        
        // Query que busca conversas onde o usuário é membro
        // Inclui última mensagem e contagem de não lidas
        $query = "SELECT 
                    c.conversation_id,
                    c.type,
                    c.name,
                    c.created_at,
                    m.content as last_message,
                    m.created_at as last_message_at,
                    (SELECT COUNT(*) FROM messages 
                     WHERE conversation_id = c.conversation_id 
                     AND status != 'READ' 
                     AND from_user_id != :user_id) as unread_count
                  FROM conversations c
                  JOIN conversation_members cm ON c.conversation_id = cm.conversation_id
                  LEFT JOIN LATERAL (
                    SELECT content, created_at 
                    FROM messages 
                    WHERE conversation_id = c.conversation_id 
                    ORDER BY created_at DESC 
                    LIMIT 1
                  ) m ON true
                  WHERE cm.user_id = :user_id
                  ORDER BY COALESCE(m.created_at, c.created_at) DESC
                  LIMIT :limit OFFSET :offset";
        
        $conversations = $this->database->fetchAll($query, [
            ':user_id' => $userId,
            ':limit' => $limit,
            ':offset' => $offset
        ]);
        
        foreach ($conversations as $conv) {
            $data = new Conversation\ConversationData();
            $data->setConversationId($conv['conversation_id']);
            $data->setType($conv['type']);
            $data->setName($conv['name'] ?? '');
            $data->setLastMessage($conv['last_message'] ?? '');
            $data->setUnreadCount((int)$conv['unread_count']);
            
            $response->getConversations()[] = $data;
        }
        
        $response->setSuccess(true);
        
    } catch (\Exception $e) {
        $this->logger->error('Failed to list conversations: ' . $e->getMessage());
        $response->setSuccess(false);
    }
    
    return $response;
}
```

## 4. Análise Crítica

### 4.1 Conformidade com o Requisito

| Aspecto | Status | Evidência |
|---------|--------|-----------|
| Criar grupo | ✅ | `CreateGroup` method |
| Múltiplos membros | ✅ | Loop de inserção em `conversation_members` |
| Broadcast | ✅ | Fan-out em `processGroupMessage` |
| Listar grupos | ✅ | `ListConversations` com type='group' |

### 4.2 Pontos Fortes

1. **Transação ACID**: Grupo e membros são criados atomicamente
2. **Roles distintos**: Admin vs Member permite controle de acesso
3. **Notificação assíncrona**: Não bloqueia a criação se push falhar

### 4.3 Limitações Identificadas

#### Limitação 1: Fan-out Ineficiente

**Problema**: Para grupos grandes, cada membro gera uma publicação Redis.

```php
// N membros = N publicações Redis
foreach ($members as $member) {
    $this->redis->publish(...);  // O(N) operações
}
```

**Solução**: Usar Redis Streams ou Kafka para batch:
```php
// Uma única publicação, WebSocket workers fazem fan-out local
$this->redis->publish("group:{$conversationId}", json_encode($message));
```

#### Limitação 2: Limite de Membros Não Definido

**Problema**: Grupo pode ter milhões de membros, causando fan-out explosivo.

**Solução**:
```php
if (count($memberIds) > 256) {
    throw new LimitExceededException('Max 256 members per group');
}
```

#### Limitação 3: Sem Validação de Usuários

**Problema**: `member_ids` pode conter UUIDs inválidos.

```php
// Não verifica se user_id existe na tabela users
$this->database->execute($memberQuery, [':user_id' => $memberId]);
// Foreign key viola, mas erro é genérico
```

**Solução**:
```php
// Validar antes de inserir
$existingUsers = $this->database->fetchColumn(
    "SELECT user_id FROM users WHERE user_id = ANY(:ids)",
    [':ids' => $memberIds]
);
$invalidUsers = array_diff($memberIds, $existingUsers);
if (!empty($invalidUsers)) {
    throw new InvalidArgumentException('Users not found: ' . implode(', ', $invalidUsers));
}
```

#### Limitação 4: Sem Operações de Gerenciamento

**Problema**: Não há endpoints para adicionar/remover membros após criação.

**Solução**: Adicionar métodos:
```protobuf
rpc AddMember(AddMemberRequest) returns (GenericResponse);
rpc RemoveMember(RemoveMemberRequest) returns (GenericResponse);
rpc UpdateMemberRole(UpdateMemberRoleRequest) returns (GenericResponse);
```
